## F21 date/time contract delivery, October 24

Baseline is `origin/main` at `1cb2001` (PR #72 merged). F21 is the next queued step; F16 calendar coverage follows it because it uses the all-day bounds. One agent implemented and validated it directly, without subagents, on branch `claude/f21-date-time-contract` (implementation commit `09fc202`).

The [date/time contract](date-time-contract.md) defines calendar dates, zoned wall times and instants, with shared fixtures generated independently from Python `zoneinfo`. Web uses date-only range arithmetic, which fixes the reproduced Chicago loop. On every client, all-day options run from the start of a date to the start of the next date in the poll zone. Skipped wall times are rejected, repeated ones take their first occurrence, and a due date covers its whole day. All-day dates display and export in the poll zone. Additive migration `20261025021513` enforces the all-day interval for new or edited rows and blocks timezone changes on polls with all-day options. Legacy rows are untouched.

Results: 9 new web tests plus 137 existing, web check/build, 149 database checks, **126 iOS tests** with wrapper build, **81 Android JVM tests** with both APK builds. One fresh simulator was created and then deleted. [Evidence](architecture-remediation-evidence-2026-10-24/f21/README.md). Two behavior changes need owner confirmation: the due date now closes at the end of the chosen date (web previously used UTC midnight, Android the start of the date, iOS the time of day the date was picked), and gap times are rejected rather than shifted. No merge, deployment or hosted change is authorized. F16 and F19 → F18 → F20 remain queued.
